# 运行与投递记录分页

## Goal

把运行列表和通知投递列表从客户端截断改为服务端分页，并提供状态、流程/通道、来源和时间范围筛选。

## Background

- 运行接口固定 `LIMIT 200`（`server-py/autoflow/handler.py:2521`），前端只对已加载数据做 8 条客户端分页。
- 投递接口固定 200 条，页面只展示前 8 条。

## Requirements

- R5.1 运行列表支持服务端分页、状态、流程、来源和时间范围筛选。
- R5.2 通知投递记录支持分页、状态、通道和时间范围筛选。
- R5.3 URL 保留查询状态，页面刷新后筛选不丢。
- R5.4 响应契约采用增量字段或版本兼容方案，避免破坏现有消费者。

## Acceptance Criteria

- [x] 服务端运行/投递接口支持 `page`、`pageSize` 及对应筛选参数，并返回总数。
- [x] 前端分页和筛选状态可通过 URL 恢复。
- [x] 大数据量下首屏只请求当前页，不一次性加载全部 200/2000 条。
- [x] 现有调用方兼容旧响应字段。

## Notes

- 不新增报表或导出功能。
- 不改变运行/投递数据模型。
