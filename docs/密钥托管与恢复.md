# 平台密钥托管与恢复（OPS-01）

本文记录 `PLATFORM_SECRET_KEY` 的托管边界与密钥丢失恢复入口。密钥用于 AES-256-GCM
加密通知渠道配置等敏感字段；密钥丢失会使这些密文不可读。

## 密钥保存（Windows 安装）

`scripts/ops/install.ps1` 不再把密钥内联写入 WinSW XML，而是写入
`%BASE%\runtime\platform-secret.key`，并把 ACL 收紧为仅 `Administrators` 与
`SYSTEM` 可读。服务通过 `PLATFORM_SECRET_KEY_FILE` 读取该文件。

- 密钥长度必须 >= 32 字符。
- 密钥文件不应随备份一起存放为明文；若需异地保管，走独立加密的密钥托管。
- 不要把手动记录的真实密钥写入 shell 历史、工单、截图或日志。

## 密钥读取优先级

`PLATFORM_SECRET_KEY` 优先于 `PLATFORM_SECRET_KEY_FILE`；生产环境两者都缺失时启动
失败。直接启动 Python 服务同样要求密钥。仅当显式设置
`AUTOFLOW_ALLOW_INSECURE_DEV_KEY=1` 且 `NODE_ENV` 不是 `production` 时，才允许
使用内置开发默认密钥。

## 密钥丢失恢复

1. 停止服务。
2. 用独立加密托管中的备份密钥重建 `runtime\platform-secret.key`，重新应用 ACL。
3. 启动服务并验证 `/ready`、登录与一条通知渠道解密/发送流程。
4. 若密钥确已不可恢复：所有 AES-GCM 密文（通知渠道配置等）将无法解密，需由
   管理员重新录入这些敏感配置，并从备份恢复其余数据。

## 主密钥轮换（版本化，P2-2）

密文带 `v<version>.` 前缀；**无前缀行视为 legacy 版本 1**。三个解密来源的版本号是
加密时所用**主密钥的稳定版本**，不是写次数计数器：

- `PLATFORM_SECRET_KEY`（或 `_FILE`）恒为**当前活跃密钥**。
- `PLATFORM_SECRET_KEY_VERSION`（整数，默认 `1`）= 活跃密钥的稳定身份；重加密后
  修剪旧版本号时它**不得回拨**（每次轮换取 `原版本 + 1`）。
- `PLATFORM_SECRET_KEY_VERSIONS` = JSON 对象 `{"1": "<更早的密钥>", ...}`，只映射
  **除活跃版本外**的其它版本，仅供解密（读取 `v<version>.` 密文时精确按版本取 key，
  不做试解）。当前活跃密钥**不要**列在这里。
- 未知版本（活跃与 retired 都找不到）解密时返回 500
  `SECRET_MASTER_KEY_VERSION_MISSING`。

完整轮换过程：

1. 先让旧密钥可在新活跃密钥下双读：停服或不停服均可，把新 key 装为活跃，旧 key
   挂到版本表，**只启动一次让服务能继续解旧行**：
   ```bash
   export PLATFORM_SECRET_KEY='<新活跃密钥>'
   export PLATFORM_SECRET_KEY_VERSION=2        # = 原活跃版本 + 1
   export PLATFORM_SECRET_KEY_VERSIONS='{"1":"<加密 v1 行的旧密钥>"}'
   ```
2. 运行重加密工具（单事务，服务可保持在线），把所有密文重写为活跃 key 与
   `v<活跃版本>.` 前缀：
   ```bash
   python scripts/ops/reencrypt-secrets.py --data-dir <PLATFORM_DATA_DIRECTORY> [--dry-run]
   ```
   覆盖 `project_secrets`、webhook `signing_secret`、通知渠道 `config` 三处存储。
3. 此时旧密钥已不再需要，可删除 `PLATFORM_SECRET_KEY_VERSIONS`（保留
   `PLATFORM_SECRET_KEY_VERSION`）；重启服务验证 `/ready`、登录与一条通知渠道
   解密/发送流程。任何时刻回滚＝恢复上一步的 env 组合（旧 key 仍是活跃的），无需
   改密文。

`PLATFORM_SECRET_KEY_VERSION` / `PLATFORM_SECRET_KEY_VERSIONS` 均为可选变量；缺省即
单密钥 v1 部署，行为与历史版本一致。

## 未验证边界

Windows 服务账户的创建、目录级最小权限 ACL 与密钥托管自动化的运行时行为需在真实
Windows 主机验证；本仓库只提供脚本与入口，不声明已在生产验证通过。
