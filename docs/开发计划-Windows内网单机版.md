# AutoFlow Workbench 完整开发计划（Windows 内网单机版）

## 1. 文档目标

本文档基于当前代码进度和已经确认的最终需求，定义 AutoFlow Workbench 从现有功能原型发展为可在公司内网长期运行的多人 Web UI 自动化平台的完整开发路线。

本计划是后续需求拆分、开发排期、阶段验收和上线判断的统一依据。

## 2. 已确认的最终需求

### 2.1 部署形态

- 系统最终部署在公司内网一台长期在线的 Windows 电脑上。
- 产品、测试、运营和管理员通过浏览器访问系统。
- 不依赖公有云，不要求 Docker、Kubernetes 或微服务。
- 前端、Platform API、数据库和 Playwright 执行器均部署在同一台 Windows 电脑上。
- Hermes Agent 可以辅助安装、升级、重启和日志排查，但不承担 Playwright 流程执行。

### 2.2 执行形态

- 第一版不建设远程 AutoFlow Agent。
- 使用服务器本机的 `ManagedRunner` 执行 Playwright Chromium。
- 第一版默认无头运行，初始并发限制为 1。
- 支持运行、取消、重试、运行至指定步骤、元素验证、截图和 Trace。
- 第一版不支持人工接管可见浏览器窗口。
- 如果未来需要在用户桌面显示浏览器、人工登录或交互式拾取元素，再单独建设 `DesktopRunner`。
- 如果未来需要多台执行电脑，再将现有 `agent/` 原型演进为 `RemoteRunner`。

### 2.3 用户与协作

- 产品负责流程设计、项目说明和普通变量配置。
- 测试负责元素、环境、数据集、验证和执行。
- 运营负责执行已发布版本、计划任务、Webhook、通知和报告。
- 发布者负责审核、发布、拒绝和回滚。
- 管理员负责用户、权限、密钥、系统设置和审计。
- 服务端是项目数据的唯一事实来源。
- 浏览器本地存储只允许保存 UI 偏好和未提交草稿缓存。

## 3. 明确不在本期范围内的内容

- 公有云部署。
- Docker 和 Kubernetes。
- 微服务拆分。
- 远程 Agent 注册、心跳、绑定和任务租约。
- 多台执行节点调度。
- CRDT 实时共同编辑。
- 可见浏览器人工接管和远程桌面串流。
- PostgreSQL、Redis、MinIO 等外部基础设施。
- 企业 AD/OIDC 单点登录；本期先完善本地账号，预留后续接入点。

## 4. 当前项目进度评估

### 4.1 已具备的能力

- 项目列表、搜索、新建、归档和项目隔离。
- 流程列表和三栏流程编辑器。
- 步骤增删、排序、变量插入、失败策略和运行至指定步骤。
- 元素库、定位方式、元素验证和验证截图。
- 普通变量、密钥变量和环境配置。
- 本地 Playwright Worker 队列、取消、重试、SSE、截图和 Trace。
- Platform 登录、工作空间、成员和基础角色。
- Platform 项目文档、版本冲突检测和本地项目导入。
- 不可变流程 Revision、发布、回滚和审计。
- 加密密钥、数据集版本、Cron、Webhook、通知和分析。
- 远程 Agent、持久调试和元素拾取原型。
- 较完整的单元测试、契约测试、Worker smoke 和浏览器 E2E。

### 4.2 当前验证基线

在制定本计划时已实际运行并通过：

- `npm run build`
- `npm run lint`
- `npm run test:unit`：2 个测试文件、33 个测试通过
- `npm run test:platform`：Platform contract smoke 通过
- `npm run test:worker`：4 组 Worker smoke 通过
- `npm run test:e2e`：25 个 Playwright 测试通过

### 4.3 主要结构性缺口

1. 项目同时以浏览器 `localStorage` 和 Platform SQLite 为数据源。
2. Platform 以整份项目 JSON 进行同步，不适合多人分别编辑不同资源。
3. 登录入口位于执行节点页面，而不是应用级登录流程。
4. 前端项目成员和后端工作空间成员使用两套角色模型。
5. Platform 运行强制要求在线 Agent，无法直接使用已经存在的本地 Worker。
6. 本地 Worker 与 Platform 运行使用两套任务表、事件表和产物模型。
7. `server/platform.ts`、`server/platform-handler.ts` 和 `server/index.ts` 体积过大。
8. 数据库建表、兼容变更和业务逻辑混合，缺少正式迁移机制。
9. 测试运行会写入仓库下的数据库和产物目录。
10. 公共模板页面仍为空壳，已有模板市场需求尚未实现。
11. 缺少生产静态文件托管、生产启动命令和 Windows 服务脚本。
12. 缺少备份恢复、日志轮转、产物保留和磁盘容量保护。

## 5. 目标架构

```text
公司内网用户浏览器
        |
        | HTTPS
        v
Windows 内网服务器
  +-- Caddy 或 IIS：TLS、反向代理、静态文件
  +-- AutoFlow Platform 服务
  |     +-- 登录和权限
  |     +-- 项目资源和版本
  |     +-- 运行、自动化和审计 API
  |     +-- SQLite
  |     +-- 后台维护任务
  +-- ManagedRunner
  |     +-- Playwright Chromium
  |     +-- 并发控制
  |     +-- 取消和超时
  |     +-- 截图和 Trace
  +-- D:\AutoFlow\data
  +-- D:\AutoFlow\artifacts
  +-- D:\AutoFlow\logs
  +-- D:\AutoFlow\backups
```

### 5.1 数据原则

- SQLite 是单机部署的唯一数据库。
- 所有业务写入通过一个 Platform 服务完成。
- 开启 WAL、foreign keys 和 busy timeout。
- 所有 Schema 变化必须通过有版本号的数据库迁移执行。
- 备份必须执行 checkpoint 或使用 SQLite backup API，不能直接复制未检查的 WAL 文件。
- `project_documents` 仅用于兼容迁移，最终由资源级数据替代。

### 5.2 执行原则

- Platform Run 只能引用已发布 Revision。
- ManagedRunner 与 Platform 共享统一的运行、事件和产物模型。
- 旧 `/api/projects/*` Worker 接口只保留为迁移兼容入口，正式版本不向内网用户暴露。
- 浏览器任务在隔离的临时目录和独立 BrowserContext 中运行。
- 密钥只在执行时解密到内存，不进入快照、日志、事件和产物元数据。

## 6. 功能范围

### 6.1 平台基础

- 应用级登录、退出和会话恢复。
- 用户邀请、账号启用/禁用和管理员重置密码。
- 工作空间、项目、成员和权限管理。
- 项目搜索、新建、归档和恢复。
- 操作审计和权限拒绝记录。

### 6.2 项目资产

- 流程、元素、变量、环境和项目设置服务端持久化。
- 资源级版本号和乐观锁。
- 冲突提示、刷新远端、复制本地修改和重新提交。
- 旧浏览器项目一次性导入。
- 密钥变量元数据与密文值分离。

### 6.3 发布与运行

- 编辑草稿、待发布、已发布、已拒绝和已废弃状态。
- 发布差异、说明、审核、拒绝和回滚。
- 服务端生成不可变发布快照。
- 手动运行、运行至指定步骤、取消、失败重试和中断恢复。
- 运行事件、步骤结果、截图、Trace 和结果详情。
- 元素验证和验证截图。

### 6.4 数据与持续回归

- CSV 和 Excel 数据集导入。
- 不可变数据集版本和预览。
- 每行数据创建独立运行。
- Cron 计划任务和时区。
- 签名 Webhook。
- 飞书、钉钉、企业微信、通用 Webhook 和邮件中继通知。
- 通知重试和投递记录。
- 运行趋势、失败分类、慢步骤和元素影响分析。

### 6.5 内部模板库

- 将流程及其依赖资产发布为内部模板。
- 搜索、分类、排序、详情和收藏。
- 创建者更新和软删除模板。
- 应用模板到有编辑权限的目标项目。
- 应用时为流程、元素、变量和环境生成新 ID。
- 不覆盖目标项目同名资产。
- 模板发布后保持冻结，源流程修改不影响模板。
- 模板快照不包含任何密钥明文。

## 8. 分阶段开发计划

### 阶段 0：基线治理（3-4 人日）

开发内容：

- 为测试创建独立临时数据库和产物目录。
- 补齐 `.gitignore`，停止新增运行数据库、WAL、截图和 Trace 到工作区状态。
- 固化当前 API、Worker 和 E2E 测试基线。
- 建立功能开关，允许新旧数据入口短期并存。
- 输出数据迁移和回滚方案。

验收标准：

- 六组基线命令全部通过。
- 连续运行两次完整测试不会污染仓库工作区。
- 不删除现有用户测试数据库和产物。

### 阶段 1：服务端模块化与数据库迁移（6-8 人日）

开发内容：

- 将 Platform 拆为 `auth`、`workspaces`、`projects`、`resources`、`revisions`、`runs`、`automations`、`templates` 和 `audit` 模块。
- 提取数据库访问、事务、统一错误、分页和审计接口。
- 建立 `schema_migrations` 表和顺序迁移机制。
- 将当前启动时的兼容 `ALTER` 逻辑迁入迁移文件。
- 保持现有 HTTP 契约可用，避免一次性重写。

验收标准：

- 空数据库和现有数据库均可升级。
- 重复启动不会重复迁移。
- 迁移失败会停止服务且不留下半完成状态。
- 当前测试全部通过。

### 阶段 2：应用级登录和统一权限（7-9 人日）

开发内容：

- 增加应用级登录页和受保护路由。
- 增加退出、会话失效、重新登录和账号禁用。
- Web UI 会话改为 HttpOnly、SameSite Cookie。
- 保留独立 API token 机制供未来集成使用。
- 统一前后端成员数据，删除浏览器中的模拟成员。
- 实现产品、测试、运营、发布者和管理员权限模板。
- 为每个修改接口补充后端权限校验。

验收标准：

- 未登录不能访问项目和模板数据。
- 前端隐藏操作不能替代后端权限校验。
- 多账号权限矩阵测试通过。
- 最后一个管理员不能被删除或降级。

### 阶段 3：服务端唯一数据源（12-15 人日）

开发内容：

- 新建项目资源模型：flows、elements、variables、environments、project settings。
- 每项资源增加 `version`、`updated_at` 和 `updated_by`。
- 增加列表、详情、新建、更新、归档和删除 API。
- 使用 `expectedVersion` 或 `ETag` 做资源级冲突检测。
- 提供 `project_documents` 到资源表的幂等迁移。
- 保留一次性浏览器本地项目导入。
- 密钥变量只保存元数据，密文进入独立 secret 表。

验收标准：

- 清空浏览器存储后重新登录，项目数据完整恢复。
- 两名用户修改不同资源不会冲突。
- 两名用户修改同一资源会收到明确冲突，而不是静默覆盖。
- 旧项目导入不会重复创建资产。

### 阶段 4：前端服务端化（10-12 人日）

开发内容：

- 使用 React Query 管理服务器数据、缓存和失效刷新。
- Zustand 仅保存流程编辑器草稿、选择状态和 UI 偏好。
- 删除 `App.tsx` 中整项目文档轮询、覆盖和冲突处理。
- 项目、流程、元素、变量、环境和设置页面改用资源 API。
- 提供保存中、已保存、离线、失败和冲突状态。
- 未提交流程草稿保存在浏览器并与服务端版本绑定。

验收标准：

- 不再存在 local/platform 两种项目模式。
- 普通用户界面不出现“导入 Platform”“绑定节点”“停止同步”等技术概念。
- 网络短暂失败时草稿不丢失，恢复后可以重试。

### 阶段 5：草稿、审核和发布（7-9 人日）

开发内容：

- 定义草稿、待审核、已发布、已拒绝和已废弃状态。
- 提交发布时由服务端读取资源并生成冻结快照。
- 支持发布说明、版本差异、审核、拒绝和回滚。
- 发布后禁止修改快照。
- 运行、计划任务和 Webhook 只能引用已发布版本。
- 发布、拒绝和回滚全部写审计。

验收标准：

- 修改草稿不会改变已经发布的版本。
- 无发布权限用户不能通过 API 发布。
- 回滚生成可审计的发布操作，不篡改历史版本。

### 阶段 6：ManagedRunner（12-15 人日）

开发内容：

- 从 `server/index.ts` 和 `agent/index.ts` 中抽取共享 `runner-core`。
- 将动作解释、变量插值、元素定位、输出采集和密钥脱敏集中到执行核心。
- 新建 `ManagedRunner`，由 Platform 本机任务队列调用。
- Platform Run 增加 `executor_type=managed`，不再要求 `agent_id`。
- 将旧 Worker 任务、事件和产物并入 Platform 模型。
- 支持并发限制、取消、超时、失败重试和服务重启恢复。
- 将元素验证接入 ManagedRunner。
- 正式内网入口禁用旧 Worker API。

验收标准：

- 无 Agent 完成“编辑 -> 提交 -> 发布 -> 执行 -> 查看报告”。
- 运行只能使用发布快照。
- 取消任务能结束浏览器和临时进程。
- 服务重启后 queued 任务可恢复，running 任务会明确标记中断或按策略重试。
- 密钥不出现在数据库明文、事件、截图文件名或 Trace 元数据中。

### 阶段 7：数据集、自动化和治理适配（7-9 人日）

开发内容：

- 将数据集参数化运行改接 ManagedRunner。
- Cron、Webhook 手动触发和通知统一创建 Platform Run。
- 为计划任务增加幂等执行键和重启补偿。
- 为内网通知地址配置显式允许列表。
- 分析报表去除 Agent 依赖字段，改为执行器字段。
- 增加数据集、计划任务、Webhook 和通知的归档/删除能力。

验收标准：

- 每行数据创建独立且可复现的运行快照。
- 服务重启不会重复创建同一计划周期的任务。
- Webhook 重放保护和签名校验通过。
- 通知失败按策略重试且不泄露运行密钥。

### 阶段 8：内部模板库（8-10 人日）

开发内容：

- 实现模板数据表、收藏表和软删除。
- 实现发布、列表、搜索、分类、排序、详情、更新、收藏和删除 API。
- 模板快照包含流程及引用的元素、变量和环境。
- 发布模板时剥离所有敏感变量值。
- 应用模板时重新生成所有资产 ID 并重写引用。
- 增加模板市场页面、详情抽屉、应用目标项目和发布入口。
- 所有模板写操作进入审计。

验收标准：

- 发布、搜索、查看、收藏和应用完整链路通过。
- 同名资产不覆盖，应用后的流程只引用新资产。
- 源流程修改不影响已发布模板。
- 未登录用户不能读取内部模板。

### 阶段 9：角色化产品界面（7-9 人日）

开发内容：

- 删除“执行节点”和“Platform”主导航。
- 增加“发布管理”和“系统管理”入口。
- 产品默认聚焦流程和需求说明。
- 测试默认聚焦元素、环境、数据集和运行。
- 运营默认聚焦已发布版本、计划任务、通知和报表。
- 补齐加载、空状态、权限不足、冲突、网络失败和危险操作确认。
- 对移动和常见桌面分辨率做布局回归。

验收标准：

- 三类业务用户不需要理解 Worker、Platform、Agent、lease 等技术概念。
- 每类角色都能独立完成其核心工作流。
- 所有按钮和菜单都与实际权限一致。

### 阶段 10：Windows 原生部署（8-10 人日）

开发内容：

- 增加生产前端、服务端构建和 `start` 命令。
- Platform 服务同源托管前端静态文件和 API，或由 Caddy/IIS 提供静态文件。
- 使用 WinSW 将 Platform 注册为 Windows 服务。
- 固定 Node.js、Playwright 和 Chromium 版本。
- 使用固定数据、产物、日志和备份目录。
- 增加 PowerShell 安装、升级、回滚、备份和恢复脚本。
- 增加 readiness、liveness、磁盘和数据库检查。
- 增加日志轮转、产物保留天数和磁盘水位保护。
- 配置 Windows 防火墙、内网 DNS 和 HTTPS。

验收标准：

- Windows 重启后服务自动启动。
- 无用户登录 Windows 桌面时，后台无头运行仍可执行。
- 升级失败可恢复到上一个版本。
- 数据库和产物可以在另一目录完成恢复演练。

### 阶段 11：试运行和上线加固（6-8 人日）

开发内容：

- 创建产品、测试、运营和管理员验收账号。
- 执行多用户冲突、权限、密钥和跨项目隔离测试。

## 12. 主要风险与控制措施

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 整项目 JSON 拆分迁移 | 数据丢失或引用错误 | 双读验证、迁移报告、原文档只读保留一个版本周期 |
| Worker 与 Platform 合并 | 运行回归 | 先抽共享 runner-core，再切 Platform，保留契约测试 |
| SQLite 单机损坏 | 平台不可用 | WAL 检查、定时备份、恢复演练、UPS |
| Chromium 残留进程 | 内存耗尽 | 每任务隔离、超时强杀、启动时清理、健康检查 |
| 多用户同时编辑 | 覆盖数据 | 资源级版本号、冲突反馈、禁止静默覆盖 |
| 内网密钥泄漏 | 严重安全问题 | HttpOnly 会话、AES-GCM、脱敏测试、最小权限账号 |
| Windows 服务无法显示桌面 | 无法人工接管浏览器 | 首版明确无头；后续单独开发 DesktopRunner |
| 产物无限增长 | 磁盘耗尽 | 保留策略、配额、水位告警、自动清理 |

## 13. 最终完成定义

同时满足以下条件，才可认为本期完整开发完成：

- 产品、测试、运营和管理员均使用真实账号登录。
- 所有项目资产以服务端为唯一数据源。
- 不再依赖 Platform 项目映射和浏览器双向同步。
- 发布版本不可变且可审核、回滚和审计。
- 不启动 AutoFlow Agent 也能完成全部后台运行。
- 数据集、计划任务、Webhook、通知和分析均使用 ManagedRunner。
- 内部模板发布和应用链路完整。
- Windows 安装、启动、升级、备份和恢复均有脚本并经过演练。
- 全部自动测试持续通过。
- 连续 7 天内网试运行无阻断性故障。
