# 安全扫描与依赖审计（QA-01 例外流程）

本文记录 `security-scan` job 的 triage 结果与例外流程，使静态扫描可阻断、依赖审计可
追踪。

## 静态扫描（bandit，阻断）

`uvx bandit -c .bandit -r server-py/autoflow -q -ll` 已通过。`.bandit` 跳过以下
误报/有意模式，并记录理由：

- `B105`：`DEFAULT_PLATFORM_SECRET` 是文档化的开发默认值；生产启动强制要求
  `PLATFORM_SECRET_KEY` 或 `PLATFORM_SECRET_KEY_FILE`。
- `B110`：`try/except: pass` 只用于非关键清理（浏览器/上下文关闭失败）。
- `B608`：SQL f-string 仅拼接 `?` 占位符列表，从不拼接用户输入；所有值都作为绑定
  参数传入。

除上述跳过项外，bandit 仍会阻断任何新的高危问题（如真实 SQL 注入、硬编码真实密钥、
subprocess 注入等）。新增代码不得扩大这些跳过范围。

## 依赖审计（npm audit / pip-audit，非阻断）

依赖审计用于**发现问题**，不自动阻断合入：Node 声明使用 `^` 范围（安装按
`package-lock.json`），Python 声明使用 `>=` 范围（安装按 uv 精确锁定的
`uv.lock`），审计结果会随锁内解析版本变化。发现的漏洞按下列流程 triage：

1. 在 PR 评论或 issue 中记录漏洞 ID、影响组件与可利用性。
2. 若可升级到无漏洞的兼容版本，直接锁定该版本（配合 `uv.lock` / `package-lock.json`）。
3. 若需非兼容升级或有业务权衡，记录例外与到期复核日期，由维护者批准。
4. 收紧方向：逐步把 `uv.lock` / `package-lock.json` 固定为已审计的安全
   版本，使依赖审计可改为阻断。
