## 一、任务目标

本任务包含两个功能点 + 强制性自测：

### A. 元素库「新建元素 → 从页面获取」

让使用人员在新建元素时不再手动编写定位器：在「新建元素」表单中点击「从页面获取」，系统打开（或复用）目标环境对应的有头 Chromium 调试浏览器；使用人员导航到目标页面并点击要定位的元素；系统自动生成候选定位器（如 testid / role / label / text / css，带匹配数量与评分）；使用人员可高亮预览候选，选定后，定位方式 / 定位值 / 页面路径 / 环境自动回填到新建元素表单；命名后保存。

约束：整个过程不得在元素库产生重复或残留元素；取消采集不得落库。

### B. 环境页面表单下拉选择

1. 新建/编辑环境时，「环境名称」支持下拉框选择（开发环境、测试环境、正式环境），同时允许手动输入自定义名称。
2. 「测试属性名」同样改为下拉框（至少含 `data-testid` / `data-test` / `data-cy` / `data-qa` / `name` / `id`），同时允许手动输入。

### C. 自测（硬性要求）

功能实现后必须完成自测，**至少完成登录测试的自测**：

## 三、执行框架（Harness Engineering）

本任务必须"能跑起来、能自证"。先搭好可复现的执行环境，所有结论以实际运行结果为准。

### 3.1 本地环境

- 安装依赖：`npm install`
- 两个终端分别启动：
  - 服务端：`npm run server`（平台 API + 本机 Worker，默认 http://127.0.0.1:8787）
  - 前端：`npm run dev -- --host 127.0.0.1 --port 4173`，浏览器打开 http://127.0.0.1:4173
- 健康检查：GET http://127.0.0.1:8787/health 应返回 `{"ok":true}`

### 3.2 平台账号与项目准备（手动自测用）

- 通过前端注册/登录账号（现有 smoke 测试也提供 `POST /api/auth/register` + `POST /api/auth/login` 的引导方式，可参照）
- 创建项目并导入到平台（前端「导入并绑定节点」），确认本地项目与平台项目映射成功、平台文档可读写

### 3.3 执行节点（Agent）准备（手动自测用）

- 在前端「执行节点」页创建注册令牌
- 启动执行节点：
  `AUTOFLOW_PLATFORM_URL=http://127.0.0.1:8787 AUTOFLOW_AGENT_REGISTRATION_TOKEN=<令牌> npm run agent`
  默认是有头 Chromium，自测需要看到真实浏览器；**不要**设置 `AUTOFLOW_AGENT_HEADLESS=1`（该变量仅供自动化 smoke 使用）
- 等待「执行节点」页显示节点在线，并把该节点绑定到自测环境

### 3.4 自测环境准备

- 新建环境：基础地址填 `https://huang1997.cloud/`（Sub2API - AI API Gateway），「测试属性名」按需选择（如 `data-testid`）

### 3.5 一键验证命令（快速参考）

## 四、验证闭环（Loop Engineering）

本任务必须"每步可验证、失败有闭环、结束有标准"。

### 4.1 阶段关卡（Phase Gate）

- 每个阶段完成 = 代码改完 + 该阶段关联测试通过 + 无 lint / 类型错误
- 关卡不通过不得进入下一阶段；不允许"后面再修"带病推进

### 4.2 失败重试规则（Fail → Fix → Re-run）

- 测试失败：先读完整日志定位根因 → 修复 → 重跑同一命令
- 同一问题最多重试 3 轮；3 轮仍失败必须停下，输出「失败报告」（命令、日志、已尝试的修复、怀疑根因），交人工决策
- 禁止：删除/放宽断言、跳过失败用例、把已知失败静默吞掉来"变绿"

### 4.3 外部站点自测的稳定性策略

- https://huang1997.cloud/ 是外部站点：网络抖动 / 站点维护导致的失败 ≠ 代码缺陷
- 失败先按指数退避重试（最多 3 次）；区分「真失败（可复现、与本次改动相关）」与「环境抖动」
- 自测结论必须写明每次运行的站点可达性，避免把站点故障误判为代码通过

### 4.4 人工检查点（Human-in-the-loop）

- 动手前：「现状确认」必须经人工核对通过后，才开始改代码
- 阶段 1（空白调试会话，地基）完成后：建议人工确认一次再继续后续阶段
- 收尾：自测报告 + 改动清单提交人工复核

### 4.5 结束条件（Exit Criteria）

- 只有同时满足以下条件，才能宣称任务完成：
  1. 验收标准（DoD）全绿
  2. 全量回归通过（至少 `lint` / `build` / `test:unit` / `test:platform` / `test:worker` / `test:agent`）
  3. 自测报告完成（含登录自测，https://huang1997.cloud/，test@qq.com / 123456）

### 4.6 变更纪律

- 每个阶段独立提交、可回滚；回滚路径 = `git revert` 对应提交
- 每阶段提交信息标注阶段号，便于追溯

## 五、必须遵守的既有约定

1. **API 向后兼容**：现有的「元素选取确认」接口支持把候选写入元素库（target=element）或绑定到流程步骤（target=step），这两种行为与返回结构保持不变，只能新增模式。
2. **权限**：沿用现有项目权限/能力校验（例如运行执行能力），空白会话只允许本项目内的环境。
3. **敏感信息**：候选定位器生成时已有按运行密钥过滤的逻辑，不得绕过；采集过程不落任何明文密钥。
4. **会话生命周期**：优先复用同环境活跃调试会话；新建会话沿用现有"空闲 15 分钟 / 最长 2 小时"回收机制。
5. **不引入新的第三方依赖**；前端样式沿用现有样式体系。
6. **环境表单默认值保持**：新建环境「测试属性名」默认仍是 `data-testid`。

## 六、实施阶段

### 阶段 1：空白调试会话（仅环境，不依赖已发布流程版本）

这是整个功能的地基，必须先做。

- 服务端「创建调试会话」接口：目前必须选择一个已发布流程版本才能创建会话；扩展为支持「仅选择环境 + 起始 URL」的空白会话。环境校验、Chromium 校验、执行节点分配等沿用现有逻辑；使用空流程/空元素快照；起始 URL 缺省用环境的基础地址。
- 浏览器执行端：空白会话启动后直接打开起始 URL 并进入就绪状态，而不是从某个流程步骤开始执行。
- 前端 API 封装与相关类型同步更新；调试会话页的「新建会话」表单增加「空白会话（仅环境 + 起始 URL）」选项（本阶段可先只做接口与测试，UI 延后）。
- **关卡**：新增/扩展冒烟测试覆盖"空白会话创建 + 导航到起始 URL"，`npm run test:agent` 通过。

### 阶段 2：采集确认支持「仅回填不落库」

- 现有「元素选取确认」接口新增一种模式：不写入元素库、不改变采集记录状态（允许同一次采集多次确认，便于使用人员在弹窗内更换候选），只返回选中的定位器信息（method / value / path / environment）与建议名称。
- 仍写入审计事件（与「写入元素库」的事件区分开）。
- 前端 API 封装与相关类型同步；服务端单测覆盖：确认后元素库数量不变、返回的候选信息正确。
- **关卡**：新增单测通过，`npm run test:unit`、`npm run test:platform` 通过。

### 阶段 3：抽取共享「元素采集面板」组件

- 将调试会话页里的采集 UI（会话列表/创建、截图轮询、启用选取、候选列表、预览、确认回调）抽成可复用组件。
- 组件接口：接收项目与可选环境；提供「选中一个候选」的回调。
- 无平台连接 / 无在线执行节点 / 会话未就绪 / 无环境时给出明确提示，不能静默失败。
- 调试会话页重构为复用该组件，保留原有「确认写入元素库」行为不回归。
- **关卡**：`npm run build`、`npm run lint`、`npm run test:unit` 通过；调试会话页手工回归无异常。

### 阶段 4：元素抽屉集成「从页面获取」

- 新建/编辑元素表单增加「从页面获取」按钮（已选环境且平台连接可用时可用；否则点击给出明确提示：未连接平台 / 未绑定执行节点 / 未选环境）。
- 点击后打开一个内嵌上述采集面板的弹窗；使用人员选定候选后，自动回填表单的「定位方式 / 定位值 / 页面路径 / 环境」。
- 若与元素库已有元素的定位器重复，提示使用人员但不阻断。
- 使用人员补填名称/描述后保存，走现有元素保存链路（前端状态与平台数据自动同步，无需另写同步逻辑）。
- **关卡**：前端单测覆盖回填与降级提示；人工在调试会话页 + 元素抽屉走通一次采集闭环。

### 阶段 5：环境表单下拉框

- 「环境名称」：由纯输入框改为「下拉选择 + 手动输入」，选项：`开发环境`、`测试环境`、`正式环境`；保留必填校验。
- 「测试属性名」：由纯输入框改为「下拉选择 + 手动输入」，选项至少：`data-testid`、`data-test`、`data-cy`、`data-qa`、`name`、`id`；保留必填校验与默认值 `data-testid`。
- 编辑环境时能正确回填现有值；保存逻辑不变（这两个字段值仍为字符串）。
- 实现建议：使用项目现有 UI 组件库中同时支持「下拉选择 + 自由输入」的控件（例如 AutoComplete 一类），不要退化成只读下拉。
- **关卡**：前端单测覆盖下拉选项与手动输入；`npm run build`、`npm run lint`、`npm run test:unit` 通过。

### 阶段 6：端到端测试与人工自测

- 端到端/冒烟测试（遵循项目现有测试写法）新增用例：

  2. 启用元素选取 → 模拟页面点击 → 轮询到候选定位器
  3. 用「仅回填不落库」模式确认 → 返回候选信息，且项目文档中元素数量不变

## 七、验收标准（DoD）

1. 元素库「新建元素」抽屉可点「从页面获取」；无平台连接 / 无绑定执行节点 / 无环境时给出明确提示而非静默失败
2. 无已发布流程版本的项目也能为该环境打开空白调试会话并导航到目标页面
3. 点击元素后生成候选定位器并按评分排序，可高亮预览，可多次选取
4. 确认后表单自动回填 method / value / path / environment；命名保存后元素出现在元素库，无重复/残留元素
5. 取消采集不产生任何草稿元素
6. 保存的元素可走现有「验证」流程（唯一匹配 / 多匹配 / 未验证）
7. 环境页面：新建环境时「环境名称」支持下拉选择（开发/测试/正式环境）与手动输入；「测试属性名」支持下拉（含 data-testid/data-test/data-cy/data-qa/name/id）与手动输入；编辑环境回填正常；默认值仍为 data-testid
8. **自测通过**：至少完成登录自测（https://huang1997.cloud/，test@qq.com / 123456），并完成元素采集全流程自测
9. 调试会话页既有功能无回归（选取 → 写入元素库、预览、步骤调试）
10. 不引入新依赖；lint / 类型检查 / 相关测试全绿

## 八、风险与注意事项

- 空白会话权限边界：只允许本项目内环境，沿用现有运行执行能力校验

- 现有「确认写入元素库 / 绑定流程步骤」两种确认行为与返回结构保持不变
- 环境名称/测试属性名改成下拉后，**必须保留手动输入能力**与既有必填校验，不能退化成只读下拉
