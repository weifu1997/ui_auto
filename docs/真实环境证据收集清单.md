# 真实环境证据收集清单

以下三项不能在仓库内伪造，必须在对应真实环境执行并留存证据。每项列出可执行入口、
预期输出与完成判据。

## BKP-02：离线异地备份与恢复演练

* 环境：Windows 部署机 + 一个可达的异地目标（网络共享/对象存储）。
* 入口：`scripts\backup.ps1 -Root D:\AutoFlow -Destination <异地路径>`，
  `scripts\restore.ps1 -Backup <异地路径> -Root D:\AutoFlow`。
* 完成判据：
  * 每日备份由计划任务触发，失败时有告警（邮件/Webhook）。
  * `manifest.json` 校验通过，篡改/缺失会中止恢复。
  * 记录一次真实恢复耗时，证明 `RPO <= 24h` 且 `RTO <= 4h`。
  * 恢复后 `/ready`、一次 run、一张历史截图/Trace 可下载。

## OPS-01：Windows 服务账户与密钥托管

* 环境：Windows 部署机。
* 入口：`scripts\install.ps1`（写入 `runtime\platform-secret.key` 并收紧 ACL）。
* 完成判据：
  * 专用服务账户以最小权限运行；密钥文件仅该账户 + Administrators + SYSTEM 可读。
  * 服务通过 `PLATFORM_SECRET_KEY_FILE` 启动，`/ready` 正常。
  * 按 `docs/密钥托管与恢复.md` 执行一次密钥丢失恢复演练。
  * 确认密钥文件不与密文一起明文备份。

## CAP-01：容量压测

* 环境：声明的目标硬件 + 一套部署。
* 入口：`AUTOFLOW_SMOKE_EMAIL=... AUTOFLOW_SMOKE_PASSWORD=... python scripts/capacity-smoke.py <base-url>`，
  并按 `docs/容量测试计划.md` 建立 10 工作区 / 100 账户 / 20 并发 / 500 runs 画像。
* 完成判据：
  * 记录 P95（只读/写）、错误率、队列深度、磁盘/内存/CPU。
  * 无饿死、无重复完成、无跨工作区误取消。
  * 500 runs >= 99% 完成，且磁盘在保留 + 备份后仍有余量。
  * 留存一段正常/降级/恢复的 soak 记录。

## 执行说明

每项完成后，把命令输出、耗时、日志与截图归档到对应 Trellis 任务的 `evidence.md`，
并把任务状态从 `in_progress` 改为 `completed`。在此之前，这些项保持「未完成」状态，
不写「已通过」。
