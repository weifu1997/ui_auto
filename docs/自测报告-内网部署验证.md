`PLATFORM_ALLOW_INSECURE_NOTIFICATION_URLS=1` + `PLATFORM_NOTIFICATION_HOST_ALLOWLIST=127.0.0.1,localhost`
（注意：allowlist 非空时只放行白名单内 host，不能与真实公网地址混用）。

## 3. 过程中发现并处理的缺陷

### 3.1 【P0 已修复】生产模式平台运行通道不可达（本地 Worker 旁路误触）

- **现象**：生产 UI「流程 → 运行」后无任何平台运行创建。
- **根因**：`platformProjectContext()`（`src/platform-context.ts:110`）只读 localStorage 项目映射（`autoflow-platform-project-map`），而生产模式从未写入该映射（`createWorkspaceProject` 与 `ServerWorkspaceSynchronizer` 均未调用 `storePlatformProjectMap`）→ 恒为空 → 流程运行/元素验证错误地落入已禁用的本机 Worker 旁路（`LEGACY_WORKER_API_DISABLED`）。
- **修复**：`src/ServerWorkspaceSynchronizer.tsx` 在 hydration（`replaceServerWorkspace`）后写入身份映射 `{本地项目id: 平台项目id}`（生产模式两者一致）。
- **验证**：修复后 C 段 `POST /runs -> 202`，ManagedRunner 成功执行。

### 3.2 【P1 未修复，建议跟进】同步器 450ms 防抖定时器随导航销毁 → 保存后立即导航丢数据

- **现象**：元素保存成功后（表格行已出现），若在 450ms 内导航到其他页面，该元素永久丢失（重载后 hydration 用服务端空数据覆盖本地）。
- **根因**：`ServerWorkspaceSynchronizer` 的 store 订阅用 `setTimeout(450ms)` 调度 `syncResources`，`page.goto`/刷新会销毁未执行的定时器；写入既不落 localStorage（生产 partialize 仅保留 activeEnvironment），也无「未完成同步」的重放机制。
- **复现**：保存元素 → 立即 reload → 服务端无该资源。
- **建议**：同步前将待写资源快照暂存（如 sessionStorage）并在 hydration 后重放；或 `beforeunload` 时同步 flush（不可靠）；或缩短 debounce + 导航前等待。

### 3.3 【P1 未修复，建议跟进】快照 checksum 含内部字段 → 无用户修改也产生新版本

- **现象**：流程保存后，后续任何资源同步都会再生成一个同内容新版本（旧版本被 supersede）；引用旧版本的计划/运行报 `409 PUBLISHED_REVISION_REQUIRED`。
- **根因**：快照 checksum 包含 `updatedAt: "刚刚"` 等内部展示字段，资源 round-trip（服务端回写 updatedAt）后序列化内容变化 → checksum 不同 → 新版本。
- **建议**：`createPlatformRevision` 的 checksum 排除内部字段（updatedAt/validation 等）或先归一化。

### 3.4 【P2 部署说明】通知本地 http 端点需白名单放行

- 仅开启 `PLATFORM_ALLOW_INSECURE_NOTIFICATION_URLS` 时 `http://127.0.0.1` 仍被拒（本次验证中 `PLATFORM_ALLOW_PRIVATE_NOTIFICATION_URLS` 未生效，原因未深究）；加 `PLATFORM_NOTIFICATION_HOST_ALLOWLIST=127.0.0.1,localhost` 后放行。真实飞书 `https://open.feishu.cn` 无需任何放行，且 allowlist 非空时反而会拦截非白名单 host（本次真实验证中已确认）。

### 3.5 【已实现】通知通道「自定义关键词」支持（真实飞书送达的必要条件）

- **背景**：带自定义关键词安全设置的飞书/钉钉/企微机器人会拒绝不含关键词的消息，且**返回 HTTP 200 + body code≠0**（本次实测 `19024` 关键词不匹配）——原投递逻辑只看 HTTP 状态，会误报成功。
- **改动**：
  - `server/platform.ts`：`postNotification` 采集响应体（限量 2KB）；投递循环读取 body 数字 `code`，非 0 判 `NOTIFICATION_REJECTED_<code>`（失败可重试）；`formatNotificationBody` 支持关键词前置（feishu/dingtalk/wecom 文本消息）。
  - `server/platform-handler.ts`：通道创建时持久化 `config.keyword`（加密落库）。
  - `src/platform-api.ts` + `src/pages/AutomationsPage.tsx`：通道表单新增「自定义关键词（可选）」。
- **实测**：关键词缺失时飞书 `19024` 拒绝并被准确标记；修复持久化后成功/失败通知均送达（code=0）。
